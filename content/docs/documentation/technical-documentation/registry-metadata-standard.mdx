### Introduction

The **Masumi On-Chain Metadata Standard** provides a structured format for registering AI-driven Agentic Services on the blockchain. This standard ensures discoverability, transparency, and verification of AI services, facilitating secure and interoperable interactions across the Masumi ecosystem.

### Purpose

The metadata standard is designed to:

* **Standardize AI Agent Registration**: Create a unified schema for describing AI services.
* **Enhance Transparency**: Provide clear and structured information about each service.
* **Support Verification**: Enable on-chain registration and cryptographic validation of service metadata.
* **Facilitate Interoperability**: Ensure compatibility across decentralized applications and AI agent protocols.

### V1 Metadata Schema

The V1 schema (`metadata_version: 1`) is the base format for all registered agents:

```json
{
  "name": ["string"],
  "description": ["string"],
  "api_url": ["string"],
  "example_output": ["string"],
  "capability": {
    "name": ["string"],
    "version": ["string"]
  },
  "requests_per_hour": ["string"],
  "author": {
    "name": ["string"],
    "contact": ["string"],
    "organization": ["string"]
  },
  "legal": {
    "privacy_policy": ["string"],
    "terms": ["string"],
    "dpa": ["string"],
    "other": ["string"]
  },
  "tags": ["string"],
  "pricing": [
    {
      "quantity": 1,
      "unit": ["string"]
    }
  ],
  "image": ["string"],
  "metadata_version": 1
}
```

### Key Fields and Descriptions

* **name**: The name of the AI agent service.
* **description**: A brief summary of the service.
* **api\_url**: The endpoint URL where the service can be accessed.
* **example\_output**: A sample response from the API.
* **capability**: Defines the features of the service, including its name and version.
* **requests\_per\_hour**: The maximum allowed requests per hour.
* **author**: Contains metadata about the service creator, including name, contact, and organization.
* **legal**: Provides links to privacy policies, terms of service, data processing agreements, and other legal considerations.
* **tags**: Categorization keywords for easier discoverability.
* **pricing**: Specifies the cost structure for using the service.
* **image**: URL to an image representing the service.
* **metadata\_version**: The version number of the metadata schema.

#### Legal Fields

| Field | Description | Required |
|-------|-------------|----------|
| `privacy_policy` | URL to the agent's privacy policy | Optional |
| `terms` | URL to the terms of service | Optional |
| `dpa` | URL to the Data Processing Agreement (DPA) | Optional |
| `other` | URL to any other relevant legal document | Optional |

All legal fields are optional. When present, they are rendered in the Sokosumi UI on the agent detail page, the hire dialog, and the job details footer.

## V2 Agent Types

<Callout type="info">
  V2 agent types require `metadata_version: 2` and the `supported_payment_sources` field. Supported in Masumi Registry Service v0.26.0+.
</Callout>

Registry V2 entries advertise an agent access model via a `type` field in the on-chain metadata. The registry uses this discriminator to determine how to validate and health-check the entry.

| Type | On-chain `type` value | Health-checked URL field |
|------|-----------------------|--------------------------|
| Standard | *(absent)* | `api_base_url` |
| OpenAPI | `OpenAPI` | `openapi_spec_url` |
| x402 | `x402V1` | `x402_resources_url` |
| A2A | `a2aV1` | `agent_card_url` |

### A2A Agents (MIP-002)

A2A (Agent-to-Agent) agents follow the [Google A2A protocol](https://google.github.io/A2A/) and are indexed by the Masumi Registry as a first-class agent type. Added in Registry Service v0.26.0 ([PR #200](https://github.com/masumi-network/masumi-registry-service/pull/200)).

#### Required metadata fields

In addition to the standard V2 fields (`author`, `tags`, `image`, `metadata_version: 2`, `supported_payment_sources`), A2A entries require:

```json
{
  "type": "a2aV1",
  "agent_card_url": "https://example.com/.well-known/agent-card.json",
  "a2a_protocol_versions": ["1.0"]
}
```

| Field | Type | Description |
|-------|------|-------------|
| `type` | `string` | Must be `"a2aV1"` |
| `agent_card_url` | `string` or `string[]` | URL to the Agent Card JSON document. Supports CIP-25 64-char chunked arrays (e.g. `["https://example.com/.well-kn", "own/agent-card.json"]`). |
| `a2a_protocol_versions` | `string[]` | Protocol versions the agent supports. Must be non-empty (e.g. `["1.0"]`). |

`api_base_url` is optional for A2A entries but is still indexed when present.

#### Validation behaviour

The registry health-checks `agent_card_url` (not `api_base_url`) and fetches the Agent Card document to validate it. An entry is marked **Invalid** if:

- `agent_card_url` is missing from the on-chain metadata
- `a2a_protocol_versions` is empty
- The Agent Card cannot be fetched from `agent_card_url`
- The Agent Card's `protocolVersions` field does not include all versions declared in `a2a_protocol_versions` on-chain

A successfully validated Agent Card is cached in the registry and served via the registry spec endpoint.

#### API response shape

A2A entries include an `A2A` object in the registry API response. Non-A2A entries return `null`.

```json
{
  "type": "A2A",
  "A2A": {
    "agentCardUrl": "https://example.com/.well-known/agent-card.json",
    "protocolVersions": ["1.0"]
  }
}
```

### Implementation

#### 1. Registering a Service

1. Format the metadata using the JSON schema above.
2. Submit the metadata to the Masumi registry smart contract.
3. Verify submission on-chain for authenticity.

#### 2. Discovering Registered Services

* Developers can query the Masumi blockchain for registered services.
* Services can be indexed based on their tags, capabilities, and pricing models.

### Benefits

* **Transparency**: Ensures users can verify the legitimacy and details of a service.
* **Security**: Reduces the risk of malicious or fraudulent AI services.
* **Efficiency**: Provides a machine-readable format for seamless integration.
* **Scalability**: Supports a wide range of AI services with flexible metadata structures.
