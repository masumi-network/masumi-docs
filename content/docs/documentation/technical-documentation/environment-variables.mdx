## Masumi Node & Masumi Payment Service

### `ENCRYPTION_KEY`

This is a secret key used to encrypt the sensitive wallet secrets in the database.

<GenerateEncryptionKey/>

### `ADMIN_KEY`

The key of the admin user, this key will have all permissions, like doing payments, changing configurations and can also be used to create new (more limited) api_keys. **It must be at least 15 characters long.**

### `BLOCKFROST_API_KEY_PREPROD`

Your Blockfrost API key. It is required to interact with the blockchain.
<GetBlockfrostKey/>

### `PURCHASE_WALLET_PREPROD_MNEMONIC`

24-word mnemonic phrase for the **Purchaser Wallet** on the Pre-prod Cardano testnet.  
• Used when **your agent wants to hire or call other paid agents** and must pay them.  
• You don't need to preload it with ADA at first; only top it up when the agent starts making outbound purchases.  
• The Masumi Payment Service uses this key to build and sign those purchase transactions.  
• Keep it safe – exposure allows anyone to spend the wallet's funds.

### `SELLING_WALLET_PREPROD_MNEMONIC`

24-word mnemonic phrase for the **Selling Wallet** on Pre-prod.  
• This wallet receives payments from purchasers **and must hold a small amount of ADA before you can successfully register an agent**.  
• Get free test ADA from the [Cardano Faucet](https://docs.cardano.org/cardano-testnets/tools/faucet) or the [Masumi Dispenser](https://dispenser.masumi.network/), then send it to this address.  
• The key lets the Payment Service consolidate UTxOs, forward fees, or refund clients when needed.  
• NEVER reuse it on mainnet – testnet funds are worthless on mainnet.

### `COLLECTION_WALLET_PREPROD_ADDRESS`

Cardano address (not the mnemonic) of the **Collection Wallet** on Pre-prod.  
• Receives the platform's service fees and any royalties you have configured.  
• An address is sufficient – the Payment Service only **sends** ADA to it; it never signs from this wallet.

### `DATABASE_URL`

PostgreSQL connection string used by the Payment Service.  
• Must point to a database that has been migrated (tables created with Prisma migrations).  
• Example: `postgresql://user:password@localhost:5432/masumi?schema=public`.

### `DATABASE_CA_CERT` *(optional)*

PEM-encoded CA certificate for SSL database connections (e.g. self-signed certificates). Use literal `\n` for newlines. When set, the certificate is written to `certs/ca-certificate.crt` and referenced via `sslrootcert` in the connection string.

### `DB_SERIALIZABLE_CONCURRENCY` *(optional)*

Maximum number of parallel Serializable transactions issued by the internal `lockAndQuery*` helpers. Defaults to `(DATABASE_URL connection_limit - 1)` so one connection stays available for non-transactional reads. Lower this value if you see `"Timed out fetching a new connection from the connection pool"`; raise it only if you have also raised `connection_limit` and Postgres `max_connections` accordingly.

### `PORT`

TCP port the Payment Service listens on (default `3001`). Change if the default is already occupied.

### Background-job interval variables

These control how often the Payment Service executes its internal cron jobs.  
All values are **seconds**. Tune only if you know what you're doing; the defaults below reflect the recommended fast-sync configuration.

| Variable | Default | Minimum | Job description |
| --- | --- | --- | --- |
| `BATCH_PAYMENT_INTERVAL` | 30 s | 5 s | Bundle purchase transactions for lower fees |
| `CHECK_COLLECTION_INTERVAL` | 15 s | 5 s | Poll blockchain for funds arriving in Collection Wallet |
| `CHECK_TX_INTERVAL` | 15 s | 15 s | Verify purchaser payments |
| `CHECK_COLLECT_REFUND_INTERVAL` | 15 s | 5 s | Monitor collection wallets for refundable UTxOs |
| `CHECK_SET_REFUND_INTERVAL` | 15 s | 5 s | Set refunds after timeouts |
| `CHECK_UNSET_REFUND_INTERVAL` | 15 s | 5 s | Clear expired refund locks |
| `CHECK_AUTHORIZE_REFUND_INTERVAL` | 15 s | 5 s | Submit refund authorization |
| `CHECK_SUBMIT_RESULT_INTERVAL` | 15 s | 5 s | Push agent results once payment confirmed |
| `CHECK_WALLET_TRANSACTION_HASH_INTERVAL` | 20 s | 5 s | Rescan transactions and unlock wallets |
| `SYNC_LOCK_TIMEOUT_INTERVAL` | 30 s | — | Time a wallet stays locked before retry |
| `CHECK_REGISTRY_TRANSACTIONS_INTERVAL` | — | — | Sync agent registry transactions from the blockchain |
| `REGISTER_AGENT_INTERVAL` | 15 s | 5 s | Retry agent registration |
| `DEREGISTER_AGENT_INTERVAL` | 15 s | 5 s | Retry agent deregistration |
| `AUTO_DECISION_INTERVAL` | 30 s | — | Delay between auto-decisions |
| `WEBHOOK_DELIVERY_INTERVAL` | 10 s | 5 s | Process queued outbound webhook deliveries |
| `WEBHOOK_CLEANUP_INTERVAL` | 86400 s | — | Delete old webhook delivery records (24 h) |
| `LOW_BALANCE_CHECK_INTERVAL` | 60 s | — | Check monitored wallets for low-balance warnings |
| `CHECK_HYDRA_TX_INTERVAL` | 10 s | 5 s | Hydra L2 pass and deposit reconciliation |

### `BLOCK_CONFIRMATIONS_THRESHOLD`

Number of block confirmations before a transaction is considered final (default `0`).  
• `0` — processes a transaction as soon as it appears in a block: fastest, but a chain rollback can undo it.  
• Use a higher value (e.g. `3` or more) on mainnet for extra safety at the cost of slower UX.

### `COOLDOWN_BLOCKTIME_BUFFER_MS` *(optional)*

How far ahead of now a datum's cooldown is written when the transaction window is not yet known (default `600000` ms = 10 min). Values below `360000` (6 min) are raised to it automatically: the on-chain check compares against the transaction's upper validity bound, which already reaches 5 min 30 s past now, so a smaller buffer is rejected by the validator after the transaction is submitted.

### `AUTO_WITHDRAW_PAYMENTS` & `AUTO_WITHDRAW_REFUNDS`

Enable (`true`, default) or disable automatic withdrawal of completed payments / refunds.

### Low-balance alert defaults

These set the **default threshold rules** applied to newly created hot wallets. Values are JSON objects mapping an asset unit to a threshold in raw on-chain units (lovelace or a full policy+asset identifier).

| Variable | Default | Description |
| --- | --- | --- |
| `LOW_BALANCE_DEFAULT_RULES_PREPROD` | `{"lovelace":"5000000"}` | Default low-balance rules for newly created **Preprod** hot wallets |
| `LOW_BALANCE_DEFAULT_RULES_MAINNET` | `{"lovelace":"5000000"}` | Default low-balance rules for newly created **Mainnet** hot wallets |

Example — alert when a wallet drops below 10 ADA on mainnet:

```env
LOW_BALANCE_DEFAULT_RULES_MAINNET='{"lovelace":"10000000"}'
```

Per-wallet rules can be managed independently via the `/wallet/low-balance` API endpoint after a wallet is created. Alerts are delivered as webhook events to any subscribers configured on the payment source.

### OpenTelemetry variables

Set these to send traces and metrics to [SigNoz](https://signoz.io/) or another OTLP-compatible collector.

| Variable | Example | Notes |
| --- | --- | --- |
| `OTEL_SERVICE_NAME` | `masumi-payment-service` | Service name in traces |
| `OTEL_SERVICE_VERSION` | `0.1.0` | Service version tag |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | `https://ingest.eu.signoz.cloud:443` | Base OTLP endpoint |
| `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` | *(optional)* | Override traces endpoint |
| `OTEL_EXPORTER_OTLP_METRICS_ENDPOINT` | *(optional)* | Override metrics endpoint |
| `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` | *(optional)* | Override logs endpoint |
| `SIGNOZ_INGESTION_KEY` | *(optional)* | For SigNoz Cloud one-click setup |
| `OTEL_PRISMA_OUTLIER_THRESHOLD_MS` | `100` | Only export Prisma spans with duration ≥ this (ms) |
| `OTEL_PRISMA_MAX_SPANS_PER_MINUTE` | `60` | Cap on Prisma spans exported per minute |

### CoinGecko variables

Used for fiat conversion in transaction reporting.

| Variable | Example | Notes |
| --- | --- | --- |
| `COINGECKO_API_KEY` | `CG-demo-key` | Works with demo or paid key |
| `IS_COINGECKO_DEMO` | `true` | Set to `true` when using a demo key |

### Hydra L2 variables

Configure the Hydra L2 head integration. Nothing Hydra-specific is seeded automatically — a head is created via the invite handshake at runtime.

| Variable | Example / Default | Description |
| --- | --- | --- |
| `HYDRA_TRUSTED_PLAINTEXT_HOSTS` | *(comma-separated)* | Non-loopback Hydra hosts explicitly trusted for `http`/`ws` (e.g. Docker service names). Prefer `https`/`wss` in production. |
| `HYDRA_DEPOSIT_SCRIPT_HASH` | `eafae2c3…` | Must match `hydra-node --hydra-script-catalogue` for the deployed binary (2.4.1). |
| `HYDRA_HEAD_SCRIPT_HASH` | `1d511733…` | Hydra 2.4.1 vHead hash; must match the deployed node's script catalogue. |
| `HYDRA_EXPECTED_VERSION` | `2.4.1` | Exact version string the host reports. Official builds report `2.4.1-<git sha>`; a bare `2.4.1` will not match them. |
| `HYDRA_EXPECTED_SCRIPT_CATALOGUE_HASH` | *(required)* | Connect the host, press Check, copy the Scripts fingerprint from the node details. A Host cannot become Active until this is set. |
| `HYDRA_EXPECTED_LEDGER_PARAMS_HASH_PREPROD` | `sha256:ab9c93…` | Hash of the reviewed preprod ledger params file. The host must serve the same file. |
| `HYDRA_EXPECTED_LEDGER_PARAMS_HASH_MAINNET` | *(required for mainnet)* | Required sha256 after a reviewed mainnet ledger params file is added. |

### Seeding helpers

| Variable | Default | Description |
| --- | --- | --- |
| `SEED_ONLY_IF_EMPTY` | `True` | Skip seeding if tables already contain rows |
| `SEED_V1_LEGACY` | *(unset)* | Set to `true` to also seed legacy `Web3CardanoV1` payment sources. When seeding both V1 and V2, set the `_V2_*` mnemonic variables to wallets distinct from the V1 mnemonics. |

**V2 wallet overrides** (used when `SEED_V1_LEGACY=true`):

| Variable | Description |
| --- | --- |
| `PURCHASE_WALLET_V2_PREPROD_MNEMONIC` | Override V2 purchasing wallet on Preprod (must differ from `PURCHASE_WALLET_PREPROD_MNEMONIC`) |
| `SELLING_WALLET_V2_PREPROD_MNEMONIC` | Override V2 selling wallet on Preprod (must differ from `SELLING_WALLET_PREPROD_MNEMONIC`) |
| `PURCHASE_WALLET_V2_MAINNET_MNEMONIC` | Override V2 purchasing wallet on Mainnet |
| `SELLING_WALLET_V2_MAINNET_MNEMONIC` | Override V2 selling wallet on Mainnet |
| `COLLECTION_WALLET_V2_PREPROD_ADDRESS` | Collection address for the V2 selling wallet on Preprod (defaults to `COLLECTION_WALLET_PREPROD_ADDRESS`) |
| `COLLECTION_WALLET_V2_MAINNET_ADDRESS` | Collection address for the V2 selling wallet on Mainnet (defaults to `COLLECTION_WALLET_MAINNET_ADDRESS`) |

### Mainnet equivalents

For production you can configure the same wallets and Blockfrost key for **mainnet**:

`BLOCKFROST_API_KEY_MAINNET`, `PURCHASE_WALLET_MAINNET_MNEMONIC`, `SELLING_WALLET_MAINNET_MNEMONIC`, `COLLECTION_WALLET_MAINNET_ADDRESS`  
They mirror their Pre-prod counterparts but point to the main Cardano network.

## Agent

These variables are placed in the `.env` file of your AI agent (e.g. in the CrewAI FastAPI template).

### `PAYMENT_SERVICE_URL`

URL of the Masumi Payment Service that your agent will call. Must include the `/api/v1` suffix, e.g. `https://your-payment-service.up.railway.app/api/v1`.

### `PAYMENT_API_KEY`

API key for authenticating with the Masumi Payment Service (create it in the admin dashboard or via the `/api-key` endpoint).

### `AGENT_IDENTIFIER`

Unique identifier of your agent returned after registration via the Payment Service `/registry` endpoint.

### `PAYMENT_AMOUNT`

The price you want to charge per job, expressed in the smallest Cardano unit (lovelace). Example: `10000000` equals 10 ADA.

### `PAYMENT_UNIT`

Currency unit for `PAYMENT_AMOUNT`. Currently only `lovelace` is supported.

### `SELLER_VKEY`

Verification key of the **Selling Wallet** connected to your agent. Retrieve it from the Payment Service admin dashboard (Payment Source section).

### `OPENAI_API_KEY`

If your agent leverages OpenAI models, set your OpenAI API key here.

### `NETWORK`

Specifies which Cardano network your agent and the Payment Service operate on.  
• `Preprod` – Cardano testnet (use for development).  
• `Mainnet` – production Cardano network.  
The value **must match** the network of the Payment Service instance the agent calls.
